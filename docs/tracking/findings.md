# 미해결 문제

## 403으로 받지 못한 기사는 기록되지 않고, 목록에서 밀려나면 영영 빠진다

- **현상**: `noble.gcs-web.com`의 일부 기사 URL이 자동 요청에 HTTP 403을 준다. 이런 기사는 수집 오류(`collectionErrors`)로만 남고 문서 기록·대기열·뉴스 목록 어디에도 없다. 다음 수집에서 다시 시도하지만, 대상은 "현재 기사 목록 상위 20건"과 "기록에 있는 미완료 작업"뿐이다. 403이 계속되는 동안 그 기사가 목록 상위 20건에서 밀려나면 다시 시도되지 않는다.
- **영향**: Noble 계약 기사가 bar 반영(제목 선별 대상)과 뉴스·공시 탭 모두에서 빠질 수 있다. 계약 자체는 다음 Noble Fleet Status 보고서에서 반영된다.
- **지금 못 푸는 이유**: 403은 발행사의 봇 차단이며, 우회하지 않는다는 원칙이 있다. 실패한 기사를 기록에 남겨 계속 재시도하게 하는 것은 기록 형식과 작업 흐름의 변경이라 이번 범위 밖이다.
- **접근**: 수집 실패한 기사 후보를 기록에 `collection-failed` 상태로 남겨 목록에서 밀려나도 재시도하거나, 최소한 제목·링크 이벤트로 뉴스 목록에 남긴다.

## `rule.md`가 현재 일당 규칙과 다르다

- **현상**: `rule.md`는 미공개 일당을 "0으로 처리하거나 추정치를 넣는다"고 한다. 실제 규칙은 공시된 일당만 쓰고, 미공개는 0이며, 추정치는 넣지 않는다(환산 일당은 공시 금액÷기간으로 코드가 따로 계산).
- **영향**: `rule.md`를 보고 일하는 사람이 추정 일당을 데이터에 넣을 수 있다.
- **지금 못 푸는 이유**: `rule.md`는 사용자가 관리하는 문서라 무엇을 남길지 사용자가 정한다.
- **접근**: 현재 규칙으로 고치거나 보관용 문서임을 표시한다.

## 운영 전환 순서와 브랜치의 복구 데이터 커밋이 겹친다

- **현상**: 계획된 전환은 "`main` 병합 뒤 `update_news --stored-results`로 복구 데이터 게시"다. 그런데 브랜치에는 이미 로컬 복구 결과 커밋(`public/data`, `data/provenance/readings.json`)이 있다. 이 커밋째로 병합하면 복구 데이터가 병합과 함께 배포되고, 이후 `--stored-results` 실행은 저장 결과 기록이 이미 완료라 일반 실행만 한다. 또 `main`의 옛 서버 워크플로는 변수 게이트 없이 6시간마다 데이터를 커밋할 수 있어, 그 사이 생긴 데이터 커밋과 `public/data`·`data/provenance`가 충돌할 수 있다.
- **영향**: 병합 방식에 따라 복구 데이터가 언제 게시되는지가 달라지고, 충돌을 잘못 풀면 manifest와 payload 해시가 어긋나 게시가 멈춘다.
- **지금 못 푸는 이유**: 병합에 데이터 커밋을 포함할지는 전환 때 사용자가 정할 일이다.
- **접근**: (a) 데이터 커밋째로 병합하고 복구 게시는 확인용으로 본다. 또는 (b) 데이터 커밋을 빼고 병합한 뒤 복구를 새로 실행한다(Codex 호출이 다시 든다). 어느 쪽이든 병합 직전 `git log origin/main -- public/data`로 새 데이터 커밋이 없는지 보고, 있으면 생성 데이터를 손으로 합치지 말고 한쪽을 택한 뒤 파이프라인을 다시 돌린다.

## 같은 문서도 읽을 때마다 결과가 다를 수 있다 (예: Noble Voyager–Shell)

- **현상**: 같은 Noble 보고서를 여러 번 읽힌 결과가 실행마다 달랐다. 한 번은 Voyager–Shell을 Sep-26~Sep-30과 금액 6억 600만 달러로 고쳤고, 다른 번은 "변경 없음"으로 두었다. 현재 결과의 Voyager–Shell row에는 금액·기간이 없어 환산 일당이 없다. 같은 조건의 Venturer–Shell은 415,068달러로 들어가 있다.
- **영향**: Voyager는 "일당 미공개"로 보이고 Dayrates 환산 점이 하나 빠진다.
- **지금 못 푸는 이유**: 검증은 화면 안전만 본다는 결정에 따라 정상 반영이다. 그 보고서 판은 완료되어 다시 읽히지 않는다.
- **접근**: 다음 Noble 보고서나 관련 기사를 기다린다. 당장 고쳐야 하면 그 보고서 기록을 지우고 다시 읽힌다(결과가 또 다를 수 있다). 반복되면 보고서 읽기만 추론 강도를 높이는 방안을 검토한다.
