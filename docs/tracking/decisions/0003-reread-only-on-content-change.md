# 0003. 문서는 내용이 바뀔 때만 다시 읽고, HTML은 본문 텍스트로 식별한다

- 날짜: 2026-10-28
- 상태: 채택

## 맥락

이전 구현은 요청문·검사 정책·기존 계약 목록(비교 맥락)이 바뀌면 이미 읽은 문서도 다시 읽었다. 요청문을 고칠 때마다 전체 재읽기와 사용 한도 소진이 일어났다. 또 Transocean 기사 페이지에는 실시간 주가 위젯이 있어 원본 HTML 바이트가 요청마다 달라졌고, 바뀌지 않은 Transocean 기사가 실행마다 다시 읽혔다.

## 결정

작업 식별은 (출처 ID, 내용 지문)뿐이다. 지문은 PDF면 파일 바이트, HTML이면 추출한 본문 텍스트다. 완료된 쌍은 다시 읽지 않는다. 요청문·스키마·모델 설정·기존 계약은 식별에 넣지 않는다.

## 대안

- **맥락·정책 해시를 식별에 포함**: 요청문 개선이 즉시 반영되지만 매번 전체 재읽기 비용이 든다.
- **HTML도 원본 바이트로 식별**: 단순하지만 페이지 주변 요소 때문에 무한 재읽기가 생긴다(실제 사례).
- **HTML을 정규화한 DOM 해시로 식별**: 위젯 같은 동적 요소를 일일이 빼야 해 사이트별 규칙이 생긴다.

## 결과

- 요청문을 개선해도 이미 읽은 문서에는 반영되지 않는다. 다음 새 판부터 적용된다. 꼭 필요하면 기록을 지워 강제로 다시 읽힌다.
- HTML 추출 코드를 바꾸면 모든 HTML 문서의 지문이 바뀌어 대량 재읽기가 일어난다. 추출 변경은 지문 이전과 함께 계획해야 한다.
- 같은 문서 재실행은 모델 호출 0회가 보장된다.
