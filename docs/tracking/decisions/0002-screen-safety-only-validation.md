# 0002. 반영 전 검증은 화면 안전만 본다

- 날짜: 2026-10-28
- 상태: 채택

## 맥락

이전 구현은 판단 이유 필수, 변경 항목마다 근거 인용 연결, 인용이 원문과 글자 단위로 같을 것, 모든 페이지·선박 확인 표시, 환산값 재검산을 요구했다. 그 결과 Codex가 바르게 읽은 Noble Apache 계약이 PDF 표 추출로 인용 글자가 어긋났다는 이유로 보류됐다. 사용자는 "필요 없는 설계는 빼자"고 했다.

## 결정

코드는 화면이 깨지지 않는 것만 확인한다: 등록 선박, 그 선박의 기존 계약 ID, 실제 ISO 날짜와 시작 ≤ 종료, 유한한 0 이상 수치(일수는 0 초과), 허용 상태값, 빈 고객·지역 없음, 적용 후 62척·회사별 척수·계약 ID 유일. 실패한 항목만 보류하고 나머지는 반영한다. 이유·인용·위치는 선택이며 반영을 막지 않는다.

## 대안

- **근거 기반 엄격 검증 유지**: 잘못된 반영은 줄지만, 맞는 반영까지 막아 데이터가 비고 보류가 쌓였다(실제 사례).
- **사람 승인 큐**: 운영자 한 명에게 매 문서 승인을 요구하게 되어 자동 갱신의 목적에 어긋난다.

## 결과

- Codex가 틀리게 읽어도 화면이 안전하면 그대로 공개된다. 고침은 다음 공시를 읽을 때 일어난다.
- 품질을 높이려면 요청문을 고쳐야 하며, 의미 검사를 코드에 추가하는 것은 이 결정을 바꾸는 일이다.
- 인용·이유가 없는 반영도 정상이다. 화면은 그 필드가 없어도 깨지지 않아야 한다.
