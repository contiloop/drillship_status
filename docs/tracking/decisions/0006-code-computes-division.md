# 0006. 환산 일당의 나눗셈은 코드가 한다

- 날짜: 2026-10-28
- 상태: 채택

## 맥락

많은 수주 공시는 일당 대신 "총 계약 금액 + 기간"만 밝힌다. 어떤 금액과 어떤 기간이 짝인지(옵션 기간 제외, 여러 선박 합산 제외)는 문장 해석이지만, 나눗셈 자체는 기계적이다. 대체 모델 시험에서 모델이 직접 계산한 환산값이 틀린 사례가 있었다.

## 결정

Codex는 `valueUsd`(기본 계약 금액)와 `baseDurationDays`(1년 = 365일, 1개월 = 365/12일)만 준다. 코드가 `valueUsd ÷ baseDurationDays`를 계산해 `derivedUsdPerDay`에 넣는다. 모델이 준 환산값은 버린다. 공시 일당(`dayRate`)과 섞지 않는다.

## 대안

- **모델이 환산값까지 계산**: 단순하지만 산술 오류가 그대로 공개된다.
- **모델 값과 코드 값을 비교해 불일치 시 보류**: 재검산 규칙이 생겨 화면 안전만 본다는 방침과 충돌한다.

## 결과

- 금액·일수 짝을 잘못 고르면(옵션 기간을 포함하는 등) 틀린 환산값이 나오며, 코드는 이를 걸러내지 않는다.
- 금액이나 일수 중 하나라도 없으면 환산값이 없다. 화면은 "일당 미공개"로 표시한다.
- 환산값은 평균 공시 일당과 시장 차트에 들어가지 않는다. Dayrates 산점도에서만 선택적으로 보인다.
