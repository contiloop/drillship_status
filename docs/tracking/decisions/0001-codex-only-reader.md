# 0001. 문서 해석은 ChatGPT 로그인 Codex CLI 하나로만 한다

- 날짜: 2026-10-28
- 상태: 채택

## 맥락

공식 보고서와 기사의 계약 조건(대략 날짜, 기간, 금액, LOA·옵션 구분, 같은 계약 여부)은 회사마다 표현이 달라, 예전의 영어 문장 정규식·보고서 파서는 새 표현이 나올 때마다 코드가 늘고 틀렸다. 운영자는 개인 한 명이고 ChatGPT 구독을 갖고 있으며, API 비용과 키 관리를 원하지 않았다.

## 결정

해석은 Codex CLI(`codex exec`)가 ChatGPT 로그인으로, 모델 `gpt-6-luna`, reasoning `medium`, Fast off, 읽기 전용 sandbox, 출력 스키마 강제로 한다. API 키·다른 모델·대체 경로는 두지 않는다. 사용 한도에 걸리면 해제 시각까지 기다린다.

## 대안

- **코드 파서 유지·확장**: 표현이 바뀔 때마다 규칙을 추가해야 했고, 실제로 날짜·금액 오해석이 반복되어 지웠다.
- **OpenAI API 키로 호출**: 서버에서도 읽을 수 있지만 비용과 키 보관·유출 위험이 생기고, 사용자가 원하지 않았다.
- **Claude Haiku 4.5(low)를 대체 모델로**: 시험했으나 환산 일당 계산 오류가 있었고 보고서 한 건에 약 9분이 걸려 채택하지 않았다.
- **한도 시 다른 모델로 대체**: 결과 품질과 형식이 모델마다 달라져 데이터가 섞인다.

## 결과

- 읽기는 운영자 Mac에서만 가능하다. 서버(GitHub Actions)는 변경 감지와 대기열 게시만 한다.
- 사용 한도에 걸리면 새 자료 반영이 몇 시간 늦어진다. 이를 줄이려 다른 모델을 끼우는 것은 이 결정을 바꾸는 일이다.
- Codex 로그인 세션이 만료되면 읽기 작업이 실패·백오프하며, 운영자가 다시 로그인해야 풀린다.
- 결과가 실행마다 다를 수 있으며, 이를 코드 규칙으로 보정하지 않는다.
