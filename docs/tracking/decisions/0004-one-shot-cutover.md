# 0004. 새 읽기 방식으로 한 번에 전환하고 예전 대기열과 호환하지 않는다

- 날짜: 2026-10-28
- 상태: 채택(전환 실행은 사용자 승인 대기)

## 맥락

예전 파이프라인은 schemaVersion 1 대기열과 다른 기록 형식을 썼다. 이전 구현은 구/신 대기열을 모두 읽는 호환 코드를 붙였고, 그 코드와 테스트가 단순화를 막았다. 운영 주체가 Mac 한 대와 서버 하나뿐이라 동시에 두 버전이 돌 이유가 없다.

## 결정

실행기는 schemaVersion 2 대기열만 읽는다. 전환은 한 번에 정해진 순서로 한다: 옛 실행기 중지 → `main` 병합·배포 확인 → 새 실행기 설치 → 서버 감지 변수 켜기 → 복구 데이터 게시 → 프로덕션 확인. 예전 기록 파일은 처음 이전할 때 읽기만 한다.

## 대안

- **구/신 대기열 동시 지원**: 순서를 신경 쓰지 않아도 되지만, 호환 코드와 테스트가 영구히 남는다.
- **단계적 전환(서버 먼저)**: 새 서버가 v2 대기열을 게시하는 동안 옛 실행기가 읽지 못해 작업이 멈춘다.

## 결과

- 전환 전에는 이 브랜치 코드로 설치된 실행기가 `main`의 v1 대기열을 거부하며 해롭지 않게 실패한다.
- 순서를 어기면(예: 실행기 없이 서버 감지를 켬, 새 코드 배포 전에 복구 데이터 게시) 작업이 멈추거나 옛 화면이 새 데이터를 받는다.
- 되돌리려면 병합을 revert하고 변수를 끄는 수밖에 없으며, 그 사이 새 형식으로 쓰인 기록은 옛 코드가 읽지 못한다.
