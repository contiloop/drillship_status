# 0008. 변경 감지는 서버가, 읽기와 계약 반영은 Mac 실행기가 한다

- 날짜: 2026-10-28
- 상태: 채택

## 맥락

Codex는 운영자 ChatGPT 로그인으로만 쓰며, 그 인증을 서버로 옮기지 않기로 했다. 한편 자료가 언제 바뀌는지 알려면 주기적 수집이 필요하고, Mac이 항상 켜져 있다는 보장은 없다. 예전에는 "6시간마다 채팅 실행" 자동화를 썼으나 일시 중지했다.

## 결정

GitHub Actions가 12시간마다 수집·지문 비교를 하고 읽을 작업을 공개 manifest의 대기열로 게시한다(모델 호출 없음). Mac의 launchd 실행기가 5분마다 그 대기열만 보고, 작업이 있을 때만 `main`의 임시 clone에서 Codex로 읽고 검증·게시한다. 계약 데이터를 바꾸는 것은 Mac 쪽 하나다.

## 대안

- **Mac만 주기 수집·읽기**: 서버가 필요 없지만 Mac이 매번 전체 수집을 하고, Mac이 꺼져 있을 때 무엇이 밀렸는지 공개 상태로 보이지 않는다.
- **서버에서 Codex 실행**: 인증 파일을 서버에 복사해야 해 금지 사항과 충돌한다.
- **상시 모델 폴링·채팅 예약 실행**: 할 일이 없어도 모델을 깨운다.

## 결과

- Mac이 꺼져 있으면 대기열이 쌓이기만 하고 반영은 Mac이 켜질 때 일어난다. 사이트는 마지막 정상 데이터를 계속 보여 준다.
- 두 게시기가 같은 파일을 `main`에 쓰므로, 경합 시 Mac은 새 clone으로 다시 하고 서버는 그 주기를 포기한다.
- 실행기 코드는 설치 checkout에서, 읽기 코드는 `main` clone에서 돈다. 설치 checkout을 `main`과 맞춰 두어야 한다.
